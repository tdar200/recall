# Recall E2E Completion (ONNX backends → UniFFI → Android app → emulator-verified APK) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the finished `recall-core` Rust engine to a working, emulator-verified Android APK: real Silero-VAD + Parakeet ASR backends, UniFFI Kotlin bridge, Compose app with capture foreground service + 4 screens + M0 soak mode.

**Architecture:** The Kotlin shell owns the mic (`AudioRecord` in a foreground service) and pushes 0.5 s PCM chunks down through one UniFFI object (`RecallEngine`, a `Mutex<EngineCore>`); the core emits only coarse events up via a UniFFI foreign trait (the existing `RecallListener`). ONNX inference (Silero VAD + Parakeet-TDT-0.6B-v2 int8 via sherpa-onnx) lives entirely inside the Rust `.so` behind the existing `Vad`/`Asr` traits, feature-gated (`onnx`) so plain `cargo test` still runs with mocks. Models are NOT bundled in the APK; they live in `getExternalFilesDir("models")` (adb-pushable, or in-app download).

**Tech Stack:** Rust (edition 2021, rust 1.86+), uniffi 0.29+, sherpa-rs (or sherpa-onnx C API — see Task 2 header), cargo-ndk, NDK r27+, Kotlin 2.x + Jetpack Compose (BOM), AGP 8.x / Gradle 8.x (Java 17), JNA (aar), Android emulator (android-36 google_apis x86_64, KVM).

## Global Constraints

- **FFI rule (from `core/src/lib.rs`): nothing high-frequency crosses the FFI.** Shell pushes large PCM chunks down (~0.5 s = 8000 samples per call); core emits only coarse per-conversation events up. Never per-frame callbacks.
- Audio format everywhere: **16 kHz, mono, 16-bit signed LE PCM**. Silero frames are **512 samples** (`FRAME_SAMPLES` in `core/src/engine.rs`).
- **No audio egress**: `cloud.rs` request builder is transcript-text-only and test-guarded; nothing in the app may upload audio. The only network calls allowed in the app: model download (in) and the optional Anthropic summary call (transcript text out, user-provided API key).
- Models and generated artifacts are **git-ignored**: `models/`, `android/app/src/main/jniLibs/`, generated UniFFI Kotlin dir. Never commit binaries > 1 MB.
- Existing 47 host tests must stay green after every task: `cargo test` (workspace root) with **no features** must pass without models, network, NDK, or device.
- TDD for all core (Rust) work. Android/Kotlin work is verified by `./gradlew assembleDebug` + the Task 7 emulator e2e (no Kotlin unit-test framework is required by this plan).
- Rust toolchain: targets `aarch64-linux-android` + `x86_64-linux-android`, `cargo-ndk`. Android SDK at `~/Android/Sdk` (platform android-36, build-tools 36.0.0, NDK 27.1.12297006). `JAVA_HOME` = system Java 17. Set `ANDROID_HOME=$HOME/Android/Sdk` and `ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/27.1.12297006` in any shell that builds Android artifacts.
- Branch: all work on `feat/e2e-android` (created from `feat/core-engine`). Commit after every task (and at every plan step marked Commit).
- The Samsung battery-soak measurement (M0 Part A numbers) **cannot be produced here** — the deliverable is the app's soak mode + updated runbook so the user can run it.
